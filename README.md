# Тест users: регистрация, авторизация с капчей, личный кабинет

Django-проект на основе примера `test_users` (github.com/narmuhamedov/TestingPO).

## Что сделано

1. **Капча при авторизации.** На форме входа стоит картинка-капча (`django-simple-captcha`). Пока капча не решена, пароль не проверяется, поэтому подобрать пароль без капчи нельзя.
2. **Тесты** (`users/tests.py`, 32 теста):
   - регистрация: успешная, пароли не совпадают, слабый пароль, занятый логин и почта, без фото, неверный телефон, дата рождения в будущем, хеширование пароля;
   - авторизация: верный вход, неверный пароль, несуществующий логин, выход (только POST);
   - капча: неверная, пустая, без полей, регистр букв, выдуманный ключ, повторное использование, просроченная, новая капча после ошибки, картинка, обновление, пароль не проверяется без капчи;
   - личный кабинет: только для вошедших, показывает данные, не показывает хеш пароля, только свои данные, полный сценарий.
3. **Результаты тестов в Word через Django.** В `settings.py` подключён свой тест-раннер `users/report_runner.py`. После `python manage.py test` он сам сохраняет `reports/test_report.docx`: дата, окружение, итог, сводка по разделам, таблица по каждому тесту (статус, время) и текст ошибок, если они есть.

## Запуск

```
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py test -v 2       # тесты + reports/test_report.docx
python manage.py runserver
```

Страницы: `/register/`, `/login/`, `/profile/`.

## Файлы отчёта

- `reports/test_report.docx` — итоговый прогон, все 32 теста пройдены.
- `reports/test_report_bug_demo.docx` — прогон, где капча специально убрана из формы входа: 9 тестов упали, отчёт это показывает.
